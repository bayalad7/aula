# 10.1 · Agente como servicio del sistema en Windows

**Origen:** plantilla `10` rellenada. Backlog Fase 2.
**Prerrequisitos:** Hito 1 cerrado (08). Conviene hacerlo antes que bloquear apps / apagar / control remoto (Fase 3), porque esas funciones necesitan que el agente corra con privilegios del sistema.
**Nota:** no agrega mensajes de protocolo nuevos; el peso está en la interfaz `ServiceControl` de `platform` y en el patrón servicio + ayudante.

## Prompt

~~~~markdown
Lee CLAUDE.md, docs/protocol.md, docs/privacidad.md y docs/progreso.md. Vamos a agregar la
función: el agente del alumno corre como servicio del sistema en Windows (patrón servicio +
ayudante en la sesión del usuario para captura y overlay), con una interfaz ServiceControl en
internal/platform. Sigue el flujo del proyecto: como no hay mensajes nuevos de protocolo, el foco
es la interfaz de plataforma y la implementación de Windows; Linux/macOS quedan para después.

## 1. Diseño (detente para que lo apruebe)
- Mensajes de protocolo: NINGUNO nuevo. Confírmalo explícitamente.
- Capacidad: no cambia el set de capacidades del agente; lo que cambia es que ahora puede correr
  con privilegios del sistema. Explica qué funciones futuras (captura con la sesión del usuario,
  bloqueo de apps, apagado, control remoto) se habilitan al tener servicio.
- Describe el patrón servicio + ayudante en Windows:
  - El servicio corre como SYSTEM, arranca con el equipo y se reinicia si falla.
  - La captura de pantalla y el overlay necesitan la sesión interactiva del usuario, así que el
    servicio lanza un proceso ayudante en la sesión activa del alumno (considera el cambio de
    sesión, cierre/inicio de sesión y varios usuarios). Explica cómo se comunican servicio y
    ayudante (p. ej. un canal local), y que el ayudante no requiere privilegios elevados.
  - Qué parte mantiene la conexión con la consola (recomienda: el servicio) y cómo le pasa al
    ayudante lo que debe mostrar.
- Privacidad: el ayudante en la sesión del usuario es quien muestra el distintivo de identidad y
  los avisos de transparencia; corriendo como servicio NO debe desaparecer esa visibilidad para el
  alumno. Documenta que correr como servicio no habilita nada oculto.
- Interfaz ServiceControl a definir en platform: instalar, desinstalar, iniciar, detener, estado.
Espera mi aprobación.

## 2. Implementación (cuando apruebe)
- Define la interfaz ServiceControl en internal/platform con una implementación por defecto que
  devuelva "no soportado", y la implementación de Windows (archivo *_windows.go) usando la API de
  servicios de Windows (p. ej. golang.org/x/sys/windows/svc y .../svc/mgr). La lógica no específica
  del SO (supervisión, relanzar el ayudante, estado) vive en internal/*, no en platform.
- Subcomandos del agente para operar el servicio (p. ej. `agente servicio instalar|desinstalar|
  iniciar|detener|estado`), pensados para instalación silenciosa por GPO (etapa 15) y para el
  instalador Inno Setup (etapa 08).
- El servicio arranca con el equipo, se reinicia ante fallos, y lanza/relanza el ayudante en la
  sesión activa; al cerrar sesión o cambiar de usuario, reubica el ayudante.
- Mantén la regla de oro: nada de APIs del SO fuera de platform.

## 3. Pruebas y cierre
- Pruebas de la lógica de supervisión/estado en internal/* (con un doble de ServiceControl; no
  instales un servicio real en las pruebas unitarias).
- Prueba de integración del ciclo instalar → iniciar → estado → reiniciar → detener → desinstalar,
  al estilo del job "servicio" de tu CI de PRISMA (solo en el runner/VM, nunca de forma que deje el
  servicio instalado). Reporta cómo verificaste el arranque automático y el reinicio ante fallo.
- Prueba manual en VM Windows: instalar el servicio, reiniciar el equipo, confirmar que el agente
  conecta solo y que el alumno ve su distintivo de identidad (el ayudante arrancó en su sesión).
- gofmt, go vet, staticcheck ./..., go test ./....
- Actualiza docs/progreso.md.

## Restricciones
- Cambios incrementales; no toques paquetes ajenos a esta función.
- Correr como servicio NUNCA debe ocultar la presencia del agente ni los avisos de transparencia al
  alumno. Documenta los permisos (SYSTEM, cuenta del servicio) y las reglas de firewall que
  requiera, y que en CI no quede un servicio instalado tras las pruebas.
~~~~
